# 关联网文站：为什么最后只做一个跳转按钮

> 2026-11-16 调研。结论先行：**不抓评论，也不在应用内展示任何站点内容，只提供跳转。**

## 一、GitHub 上有哪些现成方案

| 仓库 | 星 | 许可 | 它是什么 | 能不能用 |
|---|---:|---|---|---|
| `gedoor/legado`（阅读 3.0） | 47.2k | **无 LICENSE 文件** | 书源规则引擎，一条 JSON 描述如何抓某个站的搜索/目录/正文/评论 | **不能**。仓库没有 license，默认「保留所有权利」，复用即侵权 |
| `XIU2/Yuedu` | 12.7k | GPL-3.0 | 别人整理的书源订阅（数据，不是代码） | 不能。GPL 传染，且书源指向的多是盗版站 |
| `aoaostar/legado` | 7.4k | 无 | 同上，书源合集 | 同上 |
| `HapeLee/legado-with-MD3` | 7.0k | GPL-3.0 | 阅读的 MD3 重制版 | 同上 |
| `tickmao/Novel` | 2.0k | MIT | 书源/字体/净化规则整理 | 数据可参考，但内容依赖盗版站 |
| `fugary/calibre-douban` | 1.4k | Apache-2.0 | Calibre 的豆瓣元数据插件，按书名/ISBN 取作者、封面、简介、评分 | **可参考**，只涉及元数据，不碰评论正文 |
| `qiaohaoforever/BambooIsbn` | 503 | 无 | 中文 ISBN 查询接口 | 只能查有 ISBN 的出版物，网文没有 ISBN |
| `fugary/calibre-web-douban-api` | 464 | Apache-2.0 | 给 calibre-web 补的豆瓣 API 实现 | 可参考，同样是元数据 |

**结论**：中文网文这块，唯一成熟的「关联」实现是 Legado 的书源体系，但它恰好是**最不能碰的那种**——没有开源许可（法律上等于闭源）+ 规则指向盗版站 + 抓的是正文和评论。剩下的都是元数据插件，只能解决作者、封面、简介、评分，解决不了评论。

所以这条路不走「借用现成」，走「明确不做的边界」。

## 二、版权与合规：为什么不能在应用内显示评论

1. **评论正文是作品**。用户在站内发表的评论、书评，著作权归作者，平台享有使用权。第三方 App 抓来在自己界面里展示，属于复制 + 信息网络传播，哪怕标了来源也不构成合理使用。
2. **抓取本身违反站点条款**。起点、番茄、微信读书的用户协议都禁止未经许可的自动化抓取；实测起点对非浏览器请求直接返回 `202` 探测墙，番茄搜索接口需要签名，微信读书需要登录态。
3. **做不稳**。反爬一升级就失效，用户看到的是空页面或报错，比没有这个功能更差。
4. **真正有价值的信息（评分、口碑）本来就在站内**。用户点过去看一眼，比我们在 App 里做半截更完整，也能看到最新评论。

于是定成现在的形态：**应用内不抓、不存、不显示任何站点内容，只给一个跳转入口。**

## 三、四个站的实测（2026-11-16，本机出口）

| 站点 | 搜索地址 | 结果 |
|---|---|---|
| 微信读书 | `https://weread.qq.com/web/search/books?keyword=` | 200，书名命中 40 次，有正版书评与想法 |
| 豆瓣读书 | `https://search.douban.com/book/subject_search?search_text=` | 200，书名命中 24 次，评分与短评 |
| 番茄小说 | `https://fanqienovel.com/search/<书名>` | 200，路由式（**不是** `?q=`，那个是 404），标题回显书名 |
| 起点 | `https://www.qidian.com/search?kw=` | 无头浏览器拿到 202 探测页，真机系统浏览器正常 |

其他试过但不收的：优书网 DNS 已不通；龙空搜索路由 404（论坛，没有书籍维度）；晋江搜索页用 GBK 编码参数，URL 里塞 UTF-8 会变成乱码查询，为一个小众站加编码转换不值得；纵横能用但评论区价值低。

## 四、实现

```
src/links/sites.ts    站点列表 + 书名清洗 + 搜索地址拼接
src/links/open.ts     打开外链（App 走系统浏览器，网页走新标签页）
src/links/LinkSheet.vue  站点选择面板
```

- **书名清洗**：文件名里的 `【W18】`、`[游戏异界]`、`《》`、`（封面精校全本）`、`v1.0`、`作者：xxx`、`-作者名` 全部剥掉，只拿书名去搜。清洗规则只在前缀/后缀动手，`斗罗大陆-第一部`、`诡秘之主-宿命之环` 这类带卷次的不会被误砍。
- **入口两处**：书架长按 →「去网文站看书评」；阅读器底栏第四个按钮「书评」。
- **打开方式**：装成 App 时，Capacitor 的 `WebViewClient` 会把外站 URL 交给 Android Intent，也就是系统浏览器（`Bridge.launchIntent`）；网页版用 `window.open` 开新标签页。**不能用 `window.open(_, '_blank')` 走 App**——WebView 没实现 `onCreateWindow`，点了不会有反应。
- **不做**：自定义站点模板、评分排序、标签分组。等真的需要再从这份文档往下长。

## 五、如果以后要「应用内显示」

只有一条合法路径：申请各站开放平台的正式 API（番茄、微信读书都有内容开放平台，需资质与商务签约），或接第三方图书数据服务商。自己抓不可行，也不再考虑。
